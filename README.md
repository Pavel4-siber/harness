# REST API для общения с локальной моделью Ollama

Приложение на Spring Boot предоставляет REST API для диалогов с локальной моделью Ollama. Ответ генерируется и передаётся клиенту потоком, по мере генерации.

Каждый диалог получает `conversationId`. Передавайте его в следующих запросах, чтобы сохранить контекст предыдущих сообщений.

## Требования

- Java 25
- Docker Compose

## Запуск Ollama

Из корня проекта запустите контейнеры:

```powershell
docker compose up -d
```

Ollama будет доступна приложению и на хосте по адресу `http://localhost:11431`. При первом запуске Compose скачает модель `qwen3.5:4b` в отдельный Docker volume. Файлы модели и кэш не хранятся в репозитории.

По умолчанию используется CPU. Чтобы включить GPU, настройте поддержку GPU в Docker Compose для своей системы.

В Compose два контейнера из одного образа, а модель одна:

- `harness-ollama` постоянно работает как сервер;
- `harness-ollama-pull` один раз скачивает модель в общий том и завершается.

Загрузка модели занимает несколько минут. Прогресс и ошибки видны в логе:

```powershell
docker logs -f harness-ollama-pull
```

Убедиться, что модель загружена, можно так:

```powershell
docker exec harness-ollama ollama list
```

Пока модель не загружена, запросы к API завершаются ошибкой `MODEL_ERROR` (HTTP 502).

Контейнерам заданы DNS-серверы `8.8.8.8` и `1.1.1.1` (см. `docker-compose.yml`): встроенный DNS Docker в некоторых окружениях не может определить адрес `registry.ollama.ai`, и модель не скачивается (`server misbehaving`). Если эти серверы недоступны в вашей сети, замените их в блоках `dns` на свои.

## Запуск приложения

В отдельном окне PowerShell выполните:

```powershell
.\mvnw.cmd spring-boot:run
```

Проект использует стабильный Spring AI 2.0.2 из Maven Central.

## Настройка

Параметры можно переопределить переменными окружения:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11431` | Адрес Ollama |
| `OLLAMA_MODEL` | `qwen3.5:4b` | Имя модели |
| `OLLAMA_NUM_PREDICT` | `512` | Максимальное число токенов в ответе. При меньшем значении ответ может оборваться, при большем увеличивается время генерации |
| `CHAT_MAX_HISTORY_TURNS` | `20` | Число последних пар вопрос–ответ в контексте диалога |
| `CHAT_MAX_CONVERSATIONS` | `1000` | Максимальное число диалогов в памяти; при превышении самые старые вытесняются |
| `CHAT_CONVERSATION_TTL_MINUTES` | `60` | Через сколько минут без обращений диалог удаляется |
| `CHAT_SYSTEM_PROMPT` | Краткий промпт на английском (см. `application.properties`) | Системный промпт для каждого запроса к модели; пустое значение отключает его |
| `CHAT_TIMEZONE` | `Europe/Moscow` | Часовой пояс для текущих даты и времени, которые передаются модели |

Модель и другие настройки задаются в `application.yml`. Приложение передаёт их в каждый запрос явно.

Пример настройки в PowerShell:

```powershell
$env:OLLAMA_BASE_URL = "http://localhost:11431"
$env:OLLAMA_MODEL = "qwen3.5:4b"
$env:OLLAMA_NUM_PREDICT = "1024"
$env:CHAT_MAX_HISTORY_TURNS = "20"
$env:CHAT_TIMEZONE = "Europe/Moscow"

.\mvnw.cmd spring-boot:run
```

## API диалога

### Веб-интерфейс

Приложение предоставляет встроенный веб-интерфейс для общения с локальной моделью Ollama.

Откройте в браузере:

`http://localhost:8080/`

Интерфейс позволяет:
- **Общаться с моделью в реальном времени.** Ответ отображается по мере генерации через SSE.
- **Создавать новые диалоги.** Кнопка «Новый диалог» сбрасывает текущий контекст и начинает отдельную беседу.
- **Останавливать генерацию.** Кнопка «Стоп» прерывает текущий запрос. Частичный ответ удаляется из интерфейса и не сохраняется в истории модели.
- **Копировать ответы.** У каждого ответа ассистента есть кнопка «Копировать».
- **Отправлять сообщения с клавиатуры.** `Enter` — отправить сообщение, `Shift+Enter` — перейти на новую строку.
- **Отслеживать длину сообщения.** Максимальный размер — 8000 символов.

Состояние интерфейса, включая `conversationId` и отображаемые сообщения, сохраняется в `localStorage` браузера. После перезагрузки страницы диалог восстанавливается.

История модели при этом хранится отдельно — в памяти приложения. Поэтому после перезапуска Spring Boot сохранённые в браузере сообщения останутся видны, но контекст диалога на стороне сервера будет потерян. Для начала новой беседы используйте кнопку «Новый диалог».

### `POST /api/chat/stream`

Единственный эндпоинт общения с моделью. Ответ приходит как Server-Sent Events (SSE) по мере генерации.

Заголовки запроса:

```http
Content-Type: application/json
Accept: text/event-stream
```

Тело запроса:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `message` | Да | Сообщение пользователя; не пустое, не длиннее 8000 символов |
| `conversationId` | Нет | Идентификатор предыдущего диалога, не длиннее 64 символов. Если не указан, создаётся новый |

#### События SSE

| Событие | Данные | Когда |
| --- | --- | --- |
| `meta` | `{"conversationId": "..."}` | Первым, сразу после начала потока |
| `token` | `{"text": "..."}` | Очередная часть ответа; текст нужно склеивать по порядку |
| `done` | `{}` | Ответ успешно завершён |
| `error` | `{"code": "MODEL_ERROR", "message": "..."}` | Ошибка после начала потока. HTTP-статус к этому моменту уже отправлен (200), поэтому ошибка передаётся SSE-событием |

Полный ответ формируется на стороне клиента объединением всех значений `text` из событий `token`.

#### Пример запроса в PowerShell

Чтобы избежать проблем с экранированием кавычек и кодировкой кириллицы, сохраним тело запроса в отдельный JSON-файл:

```powershell
[IO.File]::WriteAllText(
    "$PWD\body.json",
    '{"message":"Привет, расскажи сказку"}',
    (New-Object Text.UTF8Encoding($false))
)
```

Запустим запрос и объединим полученные фрагменты ответа:

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8

$event = ''

curl.exe -sN -X POST http://localhost:8080/api/chat/stream `
    -H "Content-Type: application/json" `
    -H "Accept: text/event-stream" `
    --data-binary "@body.json" |
    ForEach-Object {
        if ($_ -match '^event:\s*(.+)$') {
            $event = $Matches[1]
        }
        elseif ($_ -match '^data:\s*(\{.*\})$') {
            $d = $Matches[1] | ConvertFrom-Json

            if ($event -eq 'token') {
                Write-Host -NoNewline $d.text
            }
            elseif ($event -eq 'error') {
                Write-Host "`n[ОШИБКА] $($d.code): $($d.message)" -ForegroundColor Red
            }
        }
    }
```

Postman показывает каждое событие отдельной строкой (новые сверху) и не объединяет токены. Для удобного просмотра используйте страницу `http://localhost:8080/`.

#### Продолжение диалога

В первом ответе приходит событие `meta` с `conversationId`. Сохраните этот идентификатор и передайте его в следующем запросе:

```json
{
  "conversationId": "идентификатор-диалога",
  "message": "Как меня зовут?"
}
```

Если `conversationId` не передан, приложение создаёт новый диалог.

### Особенности потоковой генерации

- Ответ передаётся частями, поэтому клиент может отображать его ещё до окончания генерации.
- Полный ответ попадает в историю диалога только после успешного завершения потока.
- При ошибке модели или отмене подписки до завершения генерации частичный ответ не сохраняется.
- Если модель вернула пустой ответ, генерация завершается ошибкой, а пара вопрос–ответ не добавляется в историю.
- После начала SSE-потока HTTP-статус уже нельзя изменить. Поэтому возникшие во время генерации ошибки передаются событием `error`.

## Ошибки

Ошибки, возникшие до начала SSE-потока, возвращаются в общем формате:

```json
{
  "status": 503,
  "code": "MODEL_UNAVAILABLE",
  "message": "The model service is currently unavailable",
  "details": []
}
```

Основные коды:

| HTTP | Код | Описание |
| --- | --- | --- |
| 400 | `BAD_REQUEST` | Некорректное тело запроса или ошибка валидации |
| 503 | `MODEL_UNAVAILABLE` | Ollama недоступна |
| 502 | `MODEL_ERROR` | Ошибка модели, в том числе если модель ещё не загружена |
| 500 | `INTERNAL_ERROR` | Внутренняя ошибка приложения |

Пустое или слишком длинное сообщение, а также слишком длинный `conversationId` приводят к HTTP 400.

Подробности внутренних исключений остаются в логе приложения.

Если ошибка возникает уже после начала потока, клиент получает событие `error`, а не обычный JSON-ответ с HTTP 502 или 500.

## Как обрабатывается запрос

Модель сама ничего не помнит: контекст диалога создаёт приложение и при каждом запросе заново отправляет модели системное сообщение, историю диалога и новое сообщение пользователя.

Генерация идёт фрагментами до естественного завершения или до достижения лимита `OLLAMA_NUM_PREDICT`.

- **История.** Хранится в памяти приложения отдельно для каждого `conversationId`. В контекст включаются последние 20 пар вопрос–ответ (или значение `CHAT_MAX_HISTORY_TURNS`). Число диалогов ограничено (`CHAT_MAX_CONVERSATIONS`), а диалог без обращений удаляется через `CHAT_CONVERSATION_TTL_MINUTES` минут. История сбрасывается при перезапуске и не разделяется между несколькими экземплярами приложения.
- **Системное сообщение.** Содержит системный промпт и текущие дату и время. Оно добавляется в каждый запрос, не сохраняется в истории и не расходует лимит пар.
- **Параллельные запросы.** Запросы в один диалог (включая потоковые) выполняются по очереди, чтобы история не перемешалась. Запросы в разные диалоги не блокируют друг друга, но Ollama на одной машине может обрабатывать их медленнее.
- **Токены и контекст.** Каждый запрос заново обрабатывает всю историю: чем она длиннее, тем дольше модель начинает генерировать ответ. Лимит `OLLAMA_NUM_PREDICT` ограничивает только ответ, а не историю. Контекстное окно модели ограничено; если история в него не помещается, Ollama может отбросить самые старые сообщения. Размер окна можно задать свойством `spring.ai.ollama.chat.options.num-ctx`.
- **Лог токенов.** После каждого успешного ответа приложение пишет в лог строку `Chat usage: conversation=..., promptTokens=..., completionTokens=..., historyMessages=..., numPredict=...` без текстов сообщений. `promptTokens` показывает количество токенов на входе, `completionTokens` — количество токенов в ответе. Если ответ достигает `numPredict`, добавляется предупреждение, что он, вероятно, оборван.
